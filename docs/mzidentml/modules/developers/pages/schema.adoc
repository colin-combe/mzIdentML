= Schema Reference

mzIdentML is defined by an XML Schema Definition (XSD). The schema is the
authoritative, machine-readable definition of the format and is used for
document validation, parser generation, and tooling.

== Schema Files

The schema lives in the `schema/` directory of the repository:

`schema/mzIdentML1.3.0.xsd`:: The XML Schema for mzIdentML 1.3.0 (the current version).

The schema imports the shared PSI object model, so identifications reuse the same
controlled-vocabulary (CV) and structural conventions as other HUPO-PSI formats.

== Schema Documentation

A human-readable walkthrough of the schema is embedded in the
xref:specification.adoc#model-in-xml-schema[Model in XML Schema] section of the
specification.

[NOTE]
====
That section is maintained as AsciiDoc at
`specification_document/specdoc1_3/asciidoc/model-in-xml-schema.adoc`. Its element
definitions originate from the `xsd:documentation` annotations in
`schema/mzIdentML1.3.0.xsd`, but no tool in this repository regenerates it — when the
schema changes, the AsciiDoc must be updated by hand. `./gen-docs.sh` only copies the
file into the Antora partials directory.
====

== Controlled Vocabularies

mzIdentML relies on controlled vocabularies — principally the
https://www.ebi.ac.uk/ols4/ontologies/ms[PSI-MS ontology] — to make the meaning
of identifiers, scores, and parameters unambiguous. CV terms are referenced by
accession throughout an mzIdentML document rather than being hard-coded into the
schema, which lets the format evolve without schema changes.
