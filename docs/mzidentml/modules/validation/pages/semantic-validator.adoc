= Semantic Validator

The mzIdentML *semantic validator*, mzidentml-validator, checks what the
xref:schema-validation.adoc[schema] cannot: that a file uses the required
controlled-vocabulary (CV) terms correctly and that its contents are consistent.
It comes in two forms, a *command line* tool and a desktop application with a
*graphical user interface* (GUI).

The validator also performs xref:schema-validation.adoc[schema validation],
using the schema for the version a file declares, so you do not need a separate
schema validator to check a file fully.

== What It Checks

The validator combines:

* *Schema validation* against the mzIdentML XSD;
* *CV mapping rules*, which assert that particular CV terms (or terms from a given
  branch of an ontology) appear in the required places in the document; and
* *Object rules*, coded checks of consistency, e.g. that peptide evidence matches
  the peptides it references.

It supports mzIdentML 1.1.0, 1.1.1, 1.2.0 and 1.3.0 and applies the rules for the
version a file declares. There are no semantic rules for mzIdentML 1.0.0. The rule
files and a copy of the ontologies they refer to are bundled with each release.

== Get It

The validator is developed in its own repository,
https://github.com/HUPO-PSI/mzidentml-validator[HUPO-PSI/mzidentml-validator].
Each https://github.com/HUPO-PSI/mzidentml-validator/releases/latest[release]
provides two Java jars:

* `mzidentml-validator-<version>-cmd.jar`, the command line validator; and
* `mzidentml-validator-<version>-gui.jar`, the desktop application.

Both need Java 11 or later. Everything else they need is bundled in the jar.

NOTE: The validator used to live in the `validator/` directory of the mzIdentML
repository. That copy is obsolete; only a README pointing to the new repository
remains.

== Graphical User Interface

Start the desktop application by double-clicking the GUI jar, or from a terminal:

[source,bash]
----
java -jar mzidentml-validator-<version>-gui.jar
----

Choose the file to validate and the checks to run, and the application lists the
messages it finds. For large files, give Java more memory, e.g. `java -Xmx4g -jar
...`, and see <<xml-entity-limits>>.

== Command Line

[source,bash]
----
java -Djdk.xml.maxGeneralEntitySizeLimit=0 -Djdk.xml.totalEntitySizeLimit=0 \
  -jar mzidentml-validator-<version>-cmd.jar -e -f your-file.mzid -l ERROR
----

* The two `-D` options lift the JDK's limits on the size of XML entities; see
  <<xml-entity-limits>>.
* `-e` runs the full validation: schema, CV mapping rules and object rules.
* `-f` names the file to validate. The validator picks the rules for the version
  the file declares.
* `-l` sets the lowest message level to report, e.g. `WARN` to see warnings as
  well.

The validator lists the messages it found and exits with 0 if there were none,
1 if there were messages, and 2 if it could not validate the file at all. For
large files, give Java more memory as well, e.g. `-Xmx4g`.

=== Options

Run the command line jar without arguments to list all its options. The ones used
most are:

[cols="1,3"]
|===
| Option | Effect

| `-f <file>`
| The mzIdentML file to validate (required).

| `-e`
| Full validation: schema, CV mapping rules and object rules.

| `-l <level>`
| The lowest message level to report, e.g. `ERROR` or `WARN`.

| `-x <version>`
| Validate against this schema version instead of the one the file declares.

| `-R`
| Look ontology terms up in the https://www.ebi.ac.uk/ols4/[Ontology Lookup
  Service] instead of using the bundled ontologies.

| `-m`, `-r`, `-o`
| Use your own CV mapping, coded rules or ontology configuration file instead of
  the bundled ones.
|===

Java options, such as `-D...` and `-Xmx`, go before `-jar`.

[#xml-entity-limits]
== XML Entity Size Limits

Java 24 and later limit the size of XML entities by default. On a large file with
many entity references, such as `&quot;` in attribute values, the validator then
stops during schema validation with an error like:

----
JAXP00010003: The length of entity "[xml]" is "100,001" that exceeds the "100,000"
limit set by "jdk.xml.maxGeneralEntitySizeLimit".
----

This does not mean the file is invalid. Run the validator with
`-Djdk.xml.maxGeneralEntitySizeLimit=0 -Djdk.xml.totalEntitySizeLimit=0` before
`-jar` to remove the limits; `0` means no limit, which is the default of earlier
Java versions.

== Reporting Problems

If you think the validator reports a problem wrongly, or a rule is missing,
please open an issue on the
https://github.com/HUPO-PSI/mzidentml-validator/issues[mzidentml-validator issue
tracker].
